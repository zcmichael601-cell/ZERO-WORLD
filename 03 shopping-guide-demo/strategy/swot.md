## 二、Strengths · 优势

### S1 · 架构验证完成，技术债为零
三链路路由（传统 <5ms / LLM 流式 / 兜底）已在 Demo 中跑通，经过 39 个测试用例验收，0 回归。SSE 流式、熔断器、LRU 缓存、指标监控全部到位。这是一套可直接迭代的生产级架构，不需要推倒重来。

### S2 · 意图理解层强于同阶段竞品
8 种意图类型覆盖了购物场景 95% 的主要模式；本地规则 + GLM 混合路由在规则命中时达到 4ms 响应；detail_inquiry 规格追问是当前公开竞品中少见的能力。多轮追问、槽位合并、双品牌对比提取均已验证。

### S3 · 产品定位差异化清晰
「无广告 + 高信任 + 决策透明」的定位在竞品调研中找到了明确的行业 Gap。阿里/字节的 AI 导购普遍混入广告逻辑，Rufus 在广告变现上也有妥协（响应内嵌赞助结果）。我们的定位在用户信任维度有真实的差异化空间。

### S4 · 用户界面已达演示质量
Mobile App 风格前端（SSE 流式 + 意图 badge + 商品卡片 + 规格 Sheet + 心愿单 + 发现页）具备向内部和外部展示的质量，降低了沟通产品价值的摩擦成本。

### S5 · JD 平台的潜在数据护城河
JD 自营商品具备高库存准确性、物流时效数据（今日达 / 次日达）、真实购买评价——这三类数据在 AI 推荐场景中是 Alibaba 和 ByteDance 没有的优质信号。这个护城河尚未在 Demo 中体现，但一旦打通，是真实的竞争壁垒。

## 三、Weaknesses · 劣势

### W1 · 单品类、静态数据，Demo 说服力受限
仅 48 条手机数据，无法演示多品类场景，限制了产品价值的可见性。真实用户场景（母婴、家电、服饰）无法覆盖。这是当前 Demo 阶段最直接的演示瓶颈。

### W2 · 未接入真实搜索 / 推荐算子
当前 search.py 和 recommend.py 使用 Mock 实现，与 JD 实际的搜索召回、排序、推荐系统完全脱离。Track B 调研未完成，内部系统的可复用程度未知，是 v1.1 的最大不确定性。

### W3 · 无用户数据持久化与个性化
心愿单存在 localStorage，无服务端用户 profile。每次对话冷启动，无法利用历史购买 / 浏览信号做个性化。Rufus 的 60% 转化率提升很大程度上依赖于历史行为数据。

### W4 · 商品规格数据不完整
phones.json 缺少快充瓦数、NFC、防水等级等高频查询字段，导致 detail_inquiry 对部分问题只能回答「建议查看详情页」。这削弱了规格追问功能的实际价值。

### W5 · Track B 调研缺位
系统现状调研（搜索 D1-D5 / 推荐 D1-D5 / 广告 SPU）已逾期未完成，导致：无法评估内部算子可复用程度；v1.1 技术方案无法确定；M5 综合分析缺少关键输入。

### W6 · 无购买闭环
「去购买」按钮无动作，对话导购的最终转化价值无法在 Demo 中验证。这也意味着核心成功指标（转化率提升）目前是假设而非数据。

## 四、Opportunities · 机会

### O1 · AI 购物渗透率处于 S 曲线陡坡
中国 AI 渗透率 6 个月内从 17.7% 升至 36.5%（CNNIC 2025），用户接受 AI 交互的教育成本已大幅下降。现在进入市场的产品不需要教育用户，只需要做到体验够好、足够稳定。

### O2 · 传统搜索体验正在失效
用户平均跨 4.5 个平台搜索（CBNData 2024），根本原因是单平台结果无法让用户有信心做决策。这个痛点在 2024-2026 年持续加剧，是 AI 导购最大的进入时机。

### O3 · 垂直品类深度是未被占据的差异化位置
行业普遍痛点（竞品调研 4.3）：通用导购浅，垂直品类深度不足。阿里/字节做的是横向通用覆盖；在特定品类（3C、母婴、国货护肤）做到比通用 AI 导购更专业，是可行的差异化切入点。

### O4 · 决策透明化是信任建立的低成本手段
当前主流 AI 导购（含 Rufus）普遍「给结论不给理由」。明确展示推荐逻辑（「因为你提到预算有限 + 续航好，所以优先筛了这三款」）是低技术门槛但高信任回报的差异化——我们已在 Demo 中实现，是领先现状的一个点。

### O5 · JD 物流时效是无法被复制的差异化信号
「今日达」「次日达」的时效信息是购物决策的重要因素，特别是礼品、急用场景。阿里（天猫物流）和字节（抖音商城第三方物流）在时效稳定性上与 JD 自营有差距。将物流时效融入 AI 推荐逻辑，是 JD 独有的护城河，目前还没有产品做到。

### O6 · AI 电商市场规模增速确定
AI 电商 2024 年 504 亿元，CAGR 21%，预测 2029 年达 1382 亿元（头豹 2025）。这不是预测，是资本已验证的增长曲线。平台已有强激励投入，内部资源获取窗口开放。

## 五、Threats · 威胁

### T1 · 阿里巴巴的资源压制
阿里的 AIGX 体系（六模块）+ LMA2 万亿参数 + 亿级商品库是体量上无法比拟的护城河。千问一句话下单已接近「Agentic 购物」量产。如果阿里决定在 JD 的核心品类（3C）发力，正面竞争胜算很低。**应对**：差异化定位，不与阿里在通用场景正面竞争。

### T2 · 字节的推荐算法优势
字节在推荐系统上积累了全球最强的用户兴趣图谱和内容理解能力（RankMixer-1B / HLLM / Valley2）。如果抖音电商的 AI 导购决策准确率快速提升，会对「基于内容发现的购物」场景造成压力。**应对**：聚焦货架电商（有明确需求的搜索场景），这是字节的弱项。

### T3 · Rufus 设定了极高的用户心理预期
Amazon Rufus 已把「转化率提升 60%」设定为行业基准。一旦用户习惯了 Rufus 的体验水平，对国内 AI 导购的预期也会水涨船高。推荐不准、追问生硬都会被放大为差评。**应对**：在准确率和稳定性上严格把关，宁可功能少，不能体验差。

### T4 · 大模型幻觉风险在商品场景被放大
LLM 在商品规格问答中容易产生幻觉（编造参数）。货架电商场景用户的信任门槛比内容场景更高——一次错误的规格回答会直接损害产品公信力。**应对**：规格问答优先走规则路径（已实现）；GLM 兜底时明确标注「建议查看详情页确认」。

### T5 · 内部推进阻力
AI 导购功能需要与 JD 搜索、推荐、商品数据等多个核心团队对接，内部协调成本高，数据接口开放程度不确定。Track B 调研结论将直接暴露这个威胁的实际大小。**应对**：Demo 先立项，用可视化效果驱动内部资源，降低对接门槛。

### T6 · GLM API 成本随规模线性上升
当前 Demo 阶段 API 成本可忽略，但如果 LLM 链路请求量扩大 100 倍，成本结构会发生质变。**应对**：扩大规则路径覆盖率（传统链路 / 规则答题），将 LLM 调用严格限定在高价值场景；LRU 缓存已在 v1.0 实现。

## 六、战略选项

基于 SWOT，推导出三条可行的战略方向：

### 选项 A · 垂直品类深耕（S2+S3 × O3+O5）
**核心逻辑**：在 3C 数码品类做到比阿里/字节更专业的深度推荐，结合 JD 自营物流时效，打造「3C 品类最好用的 AI 导购」。
- 关键动作：多品类数据扩充（耳机/平板）→ 商品规格知识图谱 → 物流时效集成
- 风险：品类深度需要大量商品知识维护，中长期运营成本高
- **建议优先级：高**（与现有 Demo 路径最连续，M4 调研结论支撑 v1.1 执行）

### 选项 B · 决策透明化 × 信任建立（S3 × O4）
**核心逻辑**：将推荐逻辑可视化做到极致，建立「AI 推荐比评测网站更可信」的心智。
- 关键动作：推荐理由升级（从一句话到结构化对比）→ 隐私声明 UI → 数据来源标注
- 风险：需要 LLM 生成质量高度稳定，否则透明化会暴露错误
- **建议优先级：中**（是 A 选项的能力补充，而非独立方向）

### 选项 C · 快速接入内部算子，追求生产规模（W2 × O6）
**核心逻辑**：Track B 调研完成后尽快接入真实搜索/推荐，把 Demo 转化为生产流量，用规模数据反哺模型优化。
- 关键动作：完成 Track B → 接入真实算子（v1.1）→ A/B 实验框架
- 风险：内部对接成本和时间线不确定（T5）
- **建议优先级：高**（M4 调研完成是前提，路径清晰后这条线要快）

### 综合建议

**近期（6/05-7/25）**：A + C 并行 —— Demo 侧扩充品类 + 规格字段（解 G1/G5），系统侧完成 Track B + 对接真实算子（解 G2）。

**中期（7/25-9/30）**：将 B 选项能力（决策透明化 / JD 物流时效 / 隐私声明）叠加到已接入真实算子的 v1.2 上，形成完整差异化主张。

**长期（2026 Q4+）**：在核心品类跑出 A/B 数据后，再考虑 Agentic 购买（G10）和价格追踪（G11）的投入。

## 七、结论一句话

> 架构已验证，差异化定位有效，核心 Gap 是「数据宽度 + 内部算子接入」，不是技术能力。最优路径是用已有 Demo 推动内部资源开放，Track B 调研结论出来后快速接入，用真实流量验证转化率。
