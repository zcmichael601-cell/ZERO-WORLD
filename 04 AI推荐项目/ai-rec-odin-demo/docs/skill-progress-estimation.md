## 预测如何产生

`SkillTimingHistory` 为每种执行配置保留最近 30 次成功运行，最多保留 64 个配置分组。分组依据为 Skill 配置、指令内容、模型名称、流式/非流式模式、商品 RAG 索引是否已就绪。失败和取消运行不参与学习，同组已保留的 runId 不重复计入。

当前历史只保存在服务进程内存中，重启清空，多实例之间不共享；没有预置或伪造成功记录。不同用户与输入长度暂未单独分组，因此预测是同类执行的耗时参考，而不是个体请求的时间保证。

| 样本数量 | 估计方式 | 页面提示 |
| --- | --- | --- |
| 0 | 按配置工具组合使用初始阶段预算 | 初始估计，暂无历史记录 |
| 1～4 | 初始预算与历史中位数加权，历史权重为样本数 / 5 | 结合历史记录，仍需积累数据 |
| ≥5 | 使用近期成功执行的耗时中位数 | 基于近期成功执行 |

初始预算是可调整的启发式值，不是本次执行已经测量到的耗时：加载技能 3.5 秒；工具选择每个预估决策轮次 8 秒；用户查询 0.8 秒；商品查询 0.8 秒；商品知识检索热索引 2 秒、冷索引 30 秒；天气查询 6 秒；景点查询 12 秒；结果生成按 Skill 为 60 / 90 / 110 秒；校验与衔接各 0.5 秒。具体定义位于 `SkillTimingHistory.seeds`。

阶段预算也分别学习历史中位数，随后归一化，使阶段预算之和等于总体估计。参考区间结合历史 P20 / P90 与初始预算，并至少保留总体估计上下 25% 的宽度；它不是有统计覆盖率保证的置信区间。网络波动、模型排队、输出长度、重复调用和首次索引均可能使真实耗时超出区间。预测不会修改已有模型、工具或整个 Skill 的超时限制。

## 阶段计时口径

| 阶段 | 服务端计时范围 |
| --- | --- |
| 加载技能 | 加载前的模型请求、Skill 加载工具 |
| 模型决策与工具选择 | 已加载指令但必需工具尚未齐备时的模型请求 |
| 用户信息与行为 | 用户画像和行为查询工具，合并累计 |
| 检索候选商品 | 商品搜索工具 |
| 商品知识检索 | RAG 工具，包含自动构建首次索引、向量检索等实际等待 |
| 查询天气 / 查询旅游景点 | 相应外部数据工具 |
| 模型分析与结果生成 | 必需工具已齐备后的模型请求 |
| 校验结果 | 解析并验证结构、业务字段和依据 |
| 流程衔接与其他处理 | 不在上述阶段内的执行时间，包含毫秒取整差值 |

只有配置了相应工具的 Skill 才有对应工具阶段。未知工具归入“其他工具”。模型阶段包括请求、等待分片、同轮重试与退避时间；阶段名称描述当前调用位置，不声称观察到了模型内部思考。

阶段可以反复进入，并非固定的一条流水线。使用服务端单调时钟累计计时，同一时刻只计入一个阶段；最终阶段耗时之和等于 `Run.durationMs`。进入次数不是模型 Token 数，也不等于工具调用数。中途“已完成”表示当前工具要求已经满足，模型仍可能再次查询并重新进入阶段。

## 进度条与异常处理

1. 初始估计通过 `RUN_STARTED` 中的服务端快照确认；执行中的进度事件携带最新累计计时。
2. 浏览器每 500ms 对当前活动阶段补充本机经过时间，收到服务端事件后校准。没有历史记录时也会明确标注初始估计。
3. 按阶段预计耗时加权：完成的阶段贡献完整权重，未完成阶段按累计耗时贡献部分权重。不是按完成工具数量平均分配，也不是定时器无条件涨百分比。
4. 单次执行百分比不回退，运行中最高 98%；收到 `RUN_COMPLETED` 但完整结果尚未收到时为 99%。只有最终 `SUCCESS` 结果确认后为 100%。
5. 当前阶段单次或累计预算、或总预计耗时被用尽时，剩余时间显示“暂不确定”，不长期停在“还剩 1 秒”，即使尚未超过参考区间上限也不继续承诺准确倒计时。
6. 断线后重连原会话，保留百分比和已有计时，暂停本机推算。恢复后由服务器快照校准，重复事件不会重复累计。模型重试继续计入当前阶段，不清空计时。
7. 失败或最终结果丢失时不显示 100%；有最终报告时采用报告，没有时保留最后的服务端快照，不把浏览器推算当成最终实测。

进度是经过校准的估计，仍可能在接近结束时等待较久或随阶段完成跳进；不能仅凭 elapsed time 推断模型准确剩余 Token 数。

## 接口和诊断

- `GET /api/skills/{skillId}/estimate`：返回 `Result<Estimate>`，包括 `expectedMs`、`lowerMs`、`upperMs`、`basis`、`sampleCount`、`coldStart` 与 `stages`。
- SSE `progress` 事件新增 `timing`：包括 `elapsedMs`、`activeStage`、`stages`；只有 `RUN_STARTED` 附带本次 `estimate`，避免重复发送预测配置。
- 最终 `Run.timing`：包括完整估计、阶段实测和 `predictionErrorMs`（实际总耗时减预计总耗时）。失败结果也保留计时，但不用于学习。
- 诊断日志 `RUN_TIMING`：记录 `runId`、`actualMs`、`estimatedMs`、`sampleCount`、`predictionErrorMs`，便于评估后续预测误差；不记录提示词、密钥或用户资料。

接入持久化或多实例共享存储时，应保持相同分组和成功样本过滤口径；生产环境可进一步按输入复杂度、模型版本和负载细分，并用真实历史误差决定区间宽度。
