## 发现与更新

先在本机配置好 `o2`、WebCLI 浏览器连接；需要登录或验证时在正常浏览器人工处理。采集工具不会绕过登录、验证码或访问限制，不调用猜测的内部商品 API。

```bash
o2 --help
o2 skill webcli
node scripts/jd-catalog.mjs discover https://www.jd.com/
node scripts/jd-catalog.mjs discover 'https://search.jd.com/Search?keyword=降噪耳机'
```

发现程序从商品链接或页面 `data-sku` 属性获取真实 SKU，输出规范商详链接和发现页。它不会根据产品名称让模型猜测 ID。

将要采集的商品加入待采集种子文件，每项包含 `id`、`category`、`tags`，可选 `icon`、`discoveryUrl`。当前目录最多 2000 个不重复 SKU、JSON 不超过 32 MB；每个知识文档仍不超过 16 KB，向量索引最多 2000 篇、16384 个切片、总原文不超过 32 MB。正式 `scripts/jd-product-seeds.json` 与已成功采集的商品保持一致，未取得有效商详的发现种子不算入库数量。

千件扩容发现配置为 `scripts/jd-discovery-1000.json`，补充品类配置为 `scripts/jd-discovery-supplement.json`。建议在临时种子文件中合并发现结果，审阅后采集。批量采集仍通过正常浏览器读取商详DOM，每窗口最多9件、每组最多3个页面，每组有间隔；跨域、登录或验证时停止并记录SKU，人工核实后再继续，不绕过限制。

```bash
node scripts/jd-collect-batch.mjs /tmp/jd-discovered-seeds.json \
  ai-rec-odin-demo-main/src/main/resources/catalog/jd-products.json 1000
```

批次成功后用 `apply_patch` 增量保存；已有SKU不重复抓取或刷新采集时间，重跑可继续缺失商品。缺标题、价格无效、SKU重定向或采集时间无效的记录不入库，不用空壳或重复SKU凑数；实际未达到目标时返回非零退出码。`[BATCH]`、`[COLLECTED]`、`[SKIPPED]` 记录实际进度。价格仍是采集快照而非实时报价，页面缺少的参数不生成补齐。

多品类发现可使用 `scripts/jd-discovery-categories.json`（关键词、检索分类、标签、每类数量）。从真实搜索页读取 SKU、去重后合并进现有种子，stdout 输出审阅补丁：

```bash
node scripts/jd-discover-seeds.mjs > /tmp/jd-seeds.patch
apply_patch < /tmp/jd-seeds.patch
```

扩充运动、数码与家居品类可使用 `scripts/jd-discovery-expansion.json`：运动水杯、运动手环、登山杖、露营帐篷、蓝牙音箱、无线鼠标、厨房收纳、空气炸锅，每类发现 12 个新的、不重复的 SKU。运行后仍须逐件采集商详，种子清单本身不能用于推荐或 RAG。

apply_patch < /tmp/jd-expansion-seeds.patch

apply_patch < /tmp/jd-mainstream-seeds.patch
node scripts/jd-catalog.mjs collect scripts/jd-product-seeds.json \

上述方式会刷新种子中的过期快照。只想新增而不重新采集旧数据时，可把发现命令的第二个参数指定为一个新的批次种子文件，审阅 SKU 后仅采集该批次；成功采集的种子再按 ID 合并回总种子清单。失败、重定向或需验证的商品不算采集成功，不复制其他 SKU 补齐数量，也不改写旧商品的采集时间。

购物 Skill 已支持这些新品类标签，优先使用具体的手机、冰箱、牛奶、纸巾、男装等标签，而不只使用数码、家居等宽泛标签。标签仅用于召回，不代表商品功能、营养效果或热销程度。大家电安装条件、食品过敏原和保质期、服饰尺码等未知信息应由用户确认，不由模型编造。扩库不增加每次送给模型的候选上限；当前 Skill 默认检索 6 件、优先对比 2~3 件，仍按 SKU 过滤检索证据，不把全目录塞入提示词。

```bash
node scripts/jd-catalog.mjs collect scripts/jd-product-seeds.json \
  ai-rec-odin-demo-main/src/main/resources/catalog/jd-products.json \
 > /tmp/jd-products.patch && apply_patch < /tmp/jd-products.patch
```

百件级采集建议逐件落盘并支持断点续采：

```bash
node scripts/jd-catalog.mjs collect scripts/jd-product-seeds.json \
  ai-rec-odin-demo-main/src/main/resources/catalog/jd-products.json --apply --resume
```

`--apply` 在每件商详验证通过后用小范围增量 `apply_patch` 保存并合并原目录，不删除未在本次种子中的历史商品，不反复提交整个增长中的目录；`--resume` 复用 24 小时内且分类和标签未变化的相同 SKU，剩余商品继续串行采集。无标题、SKU 重定向或浏览器访问失败会停止，已完成商品保留；不要绕过登录或验证。未加 `--apply` 时仍为原有的全批成功后输出补丁模式。采集与目录入库上限均为 500，单轮候选仍最多 12，最终对比最多 4，不将百件商品全部塞进模型上下文。

采集逐个打开商详，读取已渲染 DOM；包括商品名、已选规格、可提取参数、服务说明、页面参考价、页面库存提示、来源和时间。stdout 是可审阅的 `apply_patch` 补丁，stderr 是采集进度。全部成功后才产生更新补丁，不会因中途失败覆盖原目录。重复内容不产生更新；如补丁为空，跳过应用。

价格取当前页面价格区域原文，不把补贴、划线价、模糊价或登录提示自动当成交价；无法明确解析即 `null`。商详 DOM 因版本 / 类目变化而无法提取参数时保留空值，不能生成所谓“完整参数”。商品重定向到另一个 SKU、登录页或无标题页面会失败，不替换为其他商品。

修改后重新运行 `scripts/run-skills.sh` 会编译资源并重启。仅点 RAG 的“更新索引”不会重新读取已加载的商品目录，必须先重启应用。

## 事实与展示边界

- 页面中的价格一律是采集参考价；颜色、尺码属于该 SKU 的已选规格。成交价、补贴资格、配送与库存以购买时京东页面为准。
- 已选规格及页面原文是商品证据；人工标签只负责召回，不作为性能证据。页面宣传也不等于独立测评，不能保证主观佩戴感受、跑步效果或跨型号性能优劣。
- RAG 不检索实时价格和库存。每个 SKU 先做元数据过滤再进行向量 Top-K，不能借用其他 SKU 的知识；知识中的来源和时间用于追溯历史页面标注，即使价格快照过期也不代表文档变成实时信息。
- `SUPPORTED` 要求优势和限制均有逐字引用；`PARTIAL_EVIDENCE` 仅填写有证据的结论，允许限制为空并明确未知；`INSUFFICIENT_EVIDENCE` 不生成性能结论。不能把“资料未提供”伪装为真实缺点。
- 服务端拒绝未查询、重复、超预算、价格无效或明确缺货商品；校验 quote 是否出自当前 SKU 的真实检索片段，最终来源由服务端回填。引用校验不是完整语义事实验证，仍需评测模型对页面事实的解释。
- 前端对文本转义，仅允许匹配 SKU 的 HTTPS 京东商详链接，展示采集时间、库存待核实、参考价及原文依据。

## 上线演进建议

本实现是小规模、人工可审阅的采集导入方案，不是可承诺实时价格 / 库存的生产商品服务。生产应由团队申请获准的商品、价格、库存及搜索服务，将目录导入替换为授权服务或同步任务；具体接口与权限需向对应团队核实，不能假定网页可见就具有批量采集或长期商业使用授权。稳定知识按 SKU 增量更新向量库，价格和库存走在线工具，在推荐 / 下单前复核，保留字段来源、时效和撤销机制。
