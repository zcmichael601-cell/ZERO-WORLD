### LLM 是如何训练的？

```
【数据】万亿 Token（网页 / 书籍 / 代码）
      │
      ▼
┌─────────────────────────────────────────────┐
│  1. 预训练 Pre-training                      │
│                                             │
│  输入：[token1, token2, ..., tokenN]        │
│  任务：预测下一个 token                      │
│  损失：Loss = -log P(tokenN+1 | t1...tN)    │
│                                             │
│  本质：用反向传播，把人类所有文字里的         │
│        规律压缩进几百亿个参数里              │
└──────────────────┬──────────────────────────┘
                   │ 基座模型：能续写文本，但不懂"听指令"
                   ▼
┌─────────────────────────────────────────────┐
│  2. 监督微调 SFT                             │
│                                             │
│  数据：(问题, 高质量回答) 标注对             │
│  任务：还是预测 token，但只算回答部分的损失  │
│  损失：Loss = -log P(回答 | 问题)            │
│                                             │
│  本质：教模型"对话的格式和风格"              │
│        数据量小（万~百万级），训练快          │
└──────────────────┬──────────────────────────┘
                   │ 指令模型：会对话，但回答质量参差不齐
                   ▼
┌─────────────────────────────────────────────┐
│  3. 强化学习 RLHF / DPO                      │
│                                             │
│  RLHF：① 人工标注偏好 → ② 训练奖励模型 RM  │
│        → ③ PPO 最大化 RM 分数              │
│           目标 = E[R(回答)] - β·KL(π‖π_ref) │
│  DPO：直接在 (好回答, 差回答) 对上优化       │
│        省掉奖励模型，一步到位                │
└──────────────────┬──────────────────────────┘
                   │ 对齐模型：GPT-4 / Claude / Gemini 等
                   ▼
┌─────────────────────────────────────────────┐
│  4. 推理训练 Reasoning RL                    │
│                                             │
│  数据：有标准答案的难题（数学/代码/逻辑）    │
│  关键：让模型在 <think> 里自由"打草稿"       │
│  奖励：最终答案对 → +1，错 → 0              │
│                                             │
│  本质：RL 自动发现"想更久 = 答得更准"        │
│        模型自己学会了 Chain-of-Thought       │
└─────────────────────────────────────────────┘
                   │ 推理模型：OpenAI o1 / DeepSeek R1 等
```

每一层都在解决上一层解决不了的问题，推理模型是目前的终点，但不是终点。

| 阶段 | 核心问题 | 信号来源 |
|------|----------|----------|
| 预训练 | 语言是什么规律？ | 文本自身（无监督） |
| SFT | 怎么按要求回答？ | 人工标注的好答案 |
| RLHF/DPO | 哪个回答更好？ | 人工的偏好比较 |
| 推理训练 | 怎么把问题想清楚？ | 答案对错（自动验证） |

### LLM 相比之前的增量价值？

LLM 的核心优势在于文本理解与生成、代码辅助、知识问答、多步推理、复杂指令跟随、意图理解和 plan，在"语言密集型任务"上表现突出。

AI 之前就存在的场景，LLM 只是提升了效率：搜索、翻译、规则型客服、基础代码补全。

真正的增量场景——AI 之前几乎不可能实现的：

1. 普通人能编程：自然语言描述需求就能得到可用代码，技能门槛消失。
2. 零样本跨域知识融合：把法律、医学、用户具体情况同时推理，之前需要专家团队。
3. 非结构化文档理解：上传合同、财报、论文直接提问，之前需要人工阅读或专用系统。
4. Agent 自主任务链：给一个目标，AI 自主拆解步骤、调用工具、执行反馈，之前必须硬编码流程。
5. 个性化教育辅导：根据学生具体错误实时调整解释，之前只有昂贵家教能做到。
6. 创意与人类协同生成：头脑风暴、初稿、风格模仿，之前创意工作完全依赖人类。

判断框架：凡是过去需要"雇一个聪明的人类专家才能完成的语言密集型任务"，LLM 大概率是真增量。凡是只需要确定性规则、精确计算、实时数据，LLM 相对传统方案优势有限。

### 如何评测效果？
