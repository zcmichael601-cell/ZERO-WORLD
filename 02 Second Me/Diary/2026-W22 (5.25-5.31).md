### LLM 是如何训练的？

数据来源：万亿 Token（网页 / 书籍 / 代码）

1. **预训练 Pre-training** → 基座模型
   预测下一个 token，`Loss = -log P(tokenN+1 | t1...tN)`。把人类文字规律压缩进参数，但不懂听指令。

2. **监督微调 SFT** → 指令模型
   在 (问题, 高质量回答) 标注对上训练，只计算回答部分的损失。教模型对话格式和风格。

3. **强化学习 RLHF / DPO** → 对齐模型（GPT-4 / Claude / Gemini）
   - RLHF：人工标注偏好 → 训练奖励模型 RM → PPO 最大化分数（KL 惩罚防漂移）
   - DPO：直接在 (好回答, 差回答) 对上优化，省掉奖励模型

4. **推理训练 Reasoning RL** → 推理模型（o1 / R1）
   答对 +1 答错 0，模型在 `<think>` 里自由打草稿，自己学会了 Chain-of-Thought。

每一层都在解决上一层解决不了的问题，推理模型是目前的终点，但不是终点。

| 阶段 | 核心问题 | 信号来源 |
|------|----------|----------|
| 预训练 | 语言是什么规律？ | 文本自身（无监督） |
| SFT | 怎么按要求回答？ | 人工标注的好答案 |
| RLHF/DPO | 哪个回答更好？ | 人工的偏好比较 |
| 推理训练 | 怎么把问题想清楚？ | 答案对错（自动验证） |

### LLM 相比之前的增量价值？

LLM 的核心优势在于文本理解与生成、代码辅助、知识问答、多步推理、复杂指令跟随、意图理解和 plan，在"语言密集型任务"上表现突出。

AI 之前就存在的场景，LLM 只是提升了效率：搜索、翻译、规则型客服、基础代码补全。

真正的增量场景——AI 之前几乎不可能实现的：

1. 普通人能编程：自然语言描述需求就能得到可用代码，技能门槛消失。
2. 零样本跨域知识融合：把法律、医学、用户具体情况同时推理，之前需要专家团队。
3. 非结构化文档理解：上传合同、财报、论文直接提问，之前需要人工阅读或专用系统。
4. Agent 自主任务链：给一个目标，AI 自主拆解步骤、调用工具、执行反馈，之前必须硬编码流程。
5. 个性化教育辅导：根据学生具体错误实时调整解释，之前只有昂贵家教能做到。
6. 创意与人类协同生成：头脑风暴、初稿、风格模仿，之前创意工作完全依赖人类。

判断框架：凡是过去需要"雇一个聪明的人类专家才能完成的语言密集型任务"，LLM 大概率是真增量。凡是只需要确定性规则、精确计算、实时数据，LLM 相对传统方案优势有限。

### 如何优化效果和成本？
降低成本的方法

  1. 减少 Token 用量（最直接）

  Prompt 压缩
  - 去掉冗余措辞、例子精简化
  - 用结构化格式（JSON schema）替代自然语言描述
  - 工具：LLMLingua、Selective Context

  输出长度控制
  # 明确限制输出格式
  "用不超过3句话回答，只返回JSON，不要解释"

  上下文窗口管理
  - 滑动窗口：只保留最近 N 轮对话
  - 摘要压缩：把历史对话压缩成摘要再传入

  ---
  2. 用更便宜的模型（性价比核心）
  
  分级路由（Model Routing）
  简单任务 → 小模型（Haiku、GPT-4o-mini）
  复杂任务 → 大模型（Opus、GPT-4o）

  判断路由的方式：任务复杂度分类器、置信度阈值、规则匹配。

  Speculative Decoding（推测解码）
  - 小模型草稿 → 大模型验证，吞吐量提升 2-4x，成本不变但速度快

  ---
  3. 缓存（避免重复计算）

  KV Cache / Prompt Cache
  - Claude、GPT-4o 均支持前缀缓存
  - 固定的 system prompt、few-shot examples 只计算一次
  - 命中缓存的 token 折扣可达 50-90%

  system prompt（固定）→ 缓存
  + user message（变化）→ 只算增量

  语义缓存
  - 相似问题复用历史回答（GPTCache、Redis + embedding 相似度）

  ---
  4. 批处理（提升吞吐降低单价）
  
  - Anthropic / OpenAI 的 Batch API 成本直降 50%
  - 适合离线任务：数据标注、批量摘要、评估

  ---
  5. 自部署开源模型（彻底去掉 API 费用）

  ┌────────────────┬───────────────────────────┐
  │      场景      │           方案            │
  ├────────────────┼───────────────────────────┤
  │ 高并发固定任务 │ Llama 3 / Qwen2.5 + vLLM  │
  ├────────────────┼───────────────────────────┤
  │ 端侧/边缘      │ Gemma 2B、Phi-3 量化版    │
  ├────────────────┼───────────────────────────┤
  │ 微调专用场景   │ LoRA 微调小模型替代大模型 │
  └────────────────┴───────────────────────────┘

  自部署的隐形成本：GPU 租用、运维、模型维护，需综合算 TCO。

  ---
  决策框架

  任务量小 / 原型阶段   → 直接用 API，不优化
  任务量中等           → Prompt 压缩 + 模型路由 + Prompt Cache
  任务量大 / 成本敏感   → Batch API + 语义缓存 + 考虑自部署
  固定垂直场景         → 微调小模型，长期最优

  核心原则：先量化（算清楚每个任务花多少），再优化（找最大的浪费点），而不是无差别压缩所有 token。


## 05/27 周三
AI幻觉，主要是来源于预训练数据中本来就不存在/存在但不正确/存在且正确，但是总结错误or丢失；
AI时代产品经理的核心逻辑没有变，还是理解用户、定义问题、解决方案和推动落地。只是1）系统确定性变了，从确定性系统编程了不确定性的系统，要有评测、实验、迭代和兜底意识；2）for human/agent的交互方式变了；3）Demo输出更提效了；

  1. 训练阶段
  - RLHF / RLAIF：用人类或 AI 反馈强化真实性偏好
  - 事实增强预训练：混入高质量知识密集型语料
  - 对比解码（Contrastive Decoding）：抑制低质量子模型的输出概率

  2. 推理阶段（最实用）
  - RAG（检索增强生成）：让模型"带着资料回答"，把知识外置到可验证的数据库
  - Chain-of-Thought + 自我核查：让模型先推理再验证，或多次采样取一致答案
  - 不确定性感知：置信度低时让模型说"我不知道"而非强行回答
  - 低温采样：降低 temperature 减少随机性（代价是多样性下降）

  3. 后处理阶段
  - 事实核查管道：用独立模型或搜索引擎验证生成内容
  - 引用溯源：强制模型给出来源，无来源则拒绝
